# 칩 경제 v1

구현: `supabase/migrations/*_chip_economy.sql`. 지급은 전부 서버 함수에서, 클라이언트는 로컬 로그 수치만 보낸다.

## 원칙

- **요금제 차이는 인정한다.** 토큰을 많이 쓰는 사람(Max 등)이 칩을 더 받는다. 대신 칩은 실력(과 운)으로 따면 된다.
- **칩은 현금·실물·선물로 바꿀 수 없다.** 칩끼리 주고받는 기능도 없다. 사행성 선을 넘지 않기 위한 고정 규칙.
- **소규모 회원제 라운지라 클라이언트를 신뢰한다.** 서버는 "말이 되는지"(날짜 범위, 상한, 리셋 시각)만 검사.

## 수입

| 항목      | 규칙                                                                                               | 중복 방지                                                                |
| --------- | -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| 시작 지갑 | 1,000칩                                                                                            | 플레이어 생성 시 1회                                                     |
| 토큰 환전 | fresh 토큰(입력+출력+캐시 쓰기, 캐시 읽기 제외) 1,000개 = 1칩. 상한 없음. Claude Code + Codex 합산 | 날짜별 "지금까지 지급한 칩"을 저장하고 차액만 지급. 30초마다 보내도 안전 |
| 출근 도장 | 하루(KST) 첫 접속 +100칩                                                                           | `players.last_daily`                                                     |
| 파산 구제 | 출근 도장 때 잔액 100칩 미만이면 +300칩                                                            | 출근 도장과 같음                                                         |
| 황금 칩   | 429에 걸리면 5시간 리밋 3개, 주간 리밋 10개. 도구마다 따로 (ADR-0009)                              | 리밋 한 건(`resets_at`)당 1회                                            |

토큰은 캐시 읽기를 뺀다. 양이 압도적으로 많고(fresh의 10배 안팎) 실제 작업량과 비례하지 않아서.

### Codex

- 로그: `~/.codex/sessions/**/*.jsonl` (`CODEX_HOME`). 응답마다 남는 `token_usage_record`를 `response_id`로 센다
- Codex의 `input_tokens`는 캐시를 포함한다 → fresh = `input_tokens − cached_input_tokens + output_tokens` (reasoning은 output 안에 있음)
- 429: `rate_limits`의 창이 가득 차면(`used_percent` ≥ 100) 그 창의 `resets_at`. 창 300분 = `five_hour`, 10080분 = `seven_day`, 그 외는 10개
- 실제 429 로그로는 아직 확인 못 함

## 황금 칩

- 1개 = **공짜 100칩 베팅**. 이기면 200칩, 지면 아무것도 잃지 않음
- **리셋 시각에 소멸.** 코딩을 못 하는 그 시간 동안 쓰라고 주는 보너스
- 이전 황금 칩이 만료된 상태에서 새로 받으면 0부터 다시 시작

## 서버 검사

| RPC                             | 거절 조건                                                       |
| ------------------------------- | --------------------------------------------------------------- |
| `claim_tokens(day, fresh)`      | day가 KST 오늘 ±1일 밖 / fresh < 0 또는 5천만 초과              |
| `claim_golden(resets_at, type)` | 이미 지난 리셋 / 8일보다 먼 리셋                                |
| `oddeven_bet(..., golden)`      | 유효한 황금 칩 없음(`no_golden`) / 잔액 부족 / 마감 / 중복 베팅 |

## 게임별 배당

### 구슬 홀짝

맞히면 건 금액의 2배 (하우스 엣지 없음, 회원끼리 칩이 오가는 게임).

### 429 슬롯

릴 3개 × 가운데 한 줄. 릴 한 바퀴 26칸: 체리 6, 벨 5, BAR 4, 7 3, 429 1, 빈칸 5, 500 2.

| 결과          | 배수           |
| ------------- | -------------- |
| 429 429 429   | ×429 (잭팟)    |
| 7 7 7         | ×50            |
| BAR BAR BAR   | ×20            |
| 벨 ×3         | ×10            |
| 체리 ×3       | ×5             |
| 체리 2개      | ×3             |
| 429 둘 / 하나 | ×3 / ×1 (본전) |

| 기믹                          | 행동                                                                              |
| ----------------------------- | --------------------------------------------------------------------------------- |
| **500 Internal Server Error** | 처음 멈춘 릴에 뜨면 그 릴만 다시 돈다. 다시 돌 땐 500이 안 나와서 환수율은 그대로 |
| **VIP HOUR**                  | 황금 칩 유효 시간(= 429 리셋 전)엔 릴에 429와 빈칸이 한 칸씩 더 (28칸)            |

|               | 평소        | VIP HOUR |
| ------------- | ----------- | -------- |
| 환수율        | 93.37%      | 107.97%  |
| 당첨 확률     | 28.4%       | 34.9%    |
| 잭팟          | 1/13,824    | 1/2,197  |
| 글리치 리스핀 | 판의 약 21% | 약 20%   |

수치는 SQL로 모든 조합을 계산해 확인 (`slot_multiplier` + 리스핀 분포). 배수는 건 금액 포함. 황금 칩 스핀은 100칩짜리 공짜 스핀.
슬롯은 평소엔 하우스가 조금씩 이기는 칩 소모처, 리밋에 걸린 동안엔 회원에게 유리한 보상 시간.

200 와일드와 404 심볼은 한때 넣었다가 기믹이 너무 많아져서 뺐다 (응답 라인의 `404 Not Found`는 꽝 표시로 남음).

### 소수결 (ADR-0013)

평일(KST) 8·11·14시에 질문이 열리고 3시간 뒤 정산. 둘 중 하나를 **500칩 고정**으로 고르면, 적게 고른 쪽이 이긴다.

| 경우                             | 정산                                                       |
| -------------------------------- | ---------------------------------------------------------- |
| 참가 3명 미만 / 동점 / 전원 일치 | 무효, 500칩 그대로 돌려줌                                  |
| 그 외                            | 소수 쪽이 진 사람 칩(500 × 진 사람 수)을 똑같이 나눔(내림) |

예: 3명 중 2 대 1이면 혼자 고른 사람이 1,500칩을 받는다(+1,000). 하우스 몫은 없다.

| RPC                     | 거절 조건                                                                          |
| ----------------------- | ---------------------------------------------------------------------------------- |
| `minority_pick(choice)` | 닉네임 없음(`not_named`) / 열린 판 없음(`minority_closed`) / 이미 고름 / 잔액 부족 |

### 블랙잭 (ADR-0014)

딜러와 겨룬다. 히트 / 스탠드 / 더블다운(첫 두 장)만, 스플릿·인슈어런스 없음. 무한 덱, 딜러는 17 이상 멈춤(소프트 17 포함), 홀 카드 없음(딜러가 블랙잭이면 더블한 칩도 짐).
베팅 10 · 30 · 50 · 100, 황금 칩(100칩 공짜) 가능. 빈 자리의 AI 봇은 칩이 없다.

| 결과                 | 지급 (건 칩 포함)                                  |
| -------------------- | -------------------------------------------------- |
| 블랙잭 (첫 두 장 21) | 건 칩 × 2.5 (3:2, 내림). 딜러도 블랙잭이면 무승부  |
| 이김 / 딜러 버스트   | 건 칩 × 2 (더블이면 두 배 건 칩 × 2)               |
| 무승부               | 건 칩 그대로. 황금 칩이면 칩 대신 황금 칩 1개 반환 |
| 짐 / 버스트          | 0                                                  |

|                        | 환수율                     |
| ---------------------- | -------------------------- |
| 최적 전략              | 98.83% (하우스 엣지 1.17%) |
| 더블 없이 (황금 칩 판) | 97.58%                     |
| 딜러처럼 16 이하 히트  | 94.33%                     |

수치는 무한 덱 기대값을 끝까지 계산해 확인. 지급 1,000칩 이상이면 전광판 빅 윈.

| RPC                                 | 거절 조건                                                                                             |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `bj_bet(room, amount, golden)`      | 닉네임 없음 / 베팅 마감(`betting_closed`) / 이미 앉음 / 만석(`table_full`) / 잔액 부족 / 황금 칩 없음 |
| `bj_deal(room)`                     | 베팅 중 아님 / 안 앉음(`not_seated`) / 다른 회원도 앉음(`not_alone`)                                  |
| `bj_action(room, hit·stand·double)` | 내 차례 아님(`not_your_turn`) / 더블은 첫 두 장·황금 칩 아님·잔액 있을 때만(`cannot_double`)          |

## 나중에 볼 것

- 실제로 돌려보고 인플레이션 확인: 헤비 유저가 하루 수천 칩을 받으면 베팅 단위(10/50/100/500)도 같이 올려야 할 수 있음
- 리밋 직전 "막판 스퍼트" 보너스, 다른 회원이 429에 걸리면 알림 같은 소셜 요소
