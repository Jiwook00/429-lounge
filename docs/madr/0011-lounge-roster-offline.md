# 라운지 명부: 접속 중이 아닌 회원도 "오프라인 · 3시간 전"으로

## 배경과 문제

[ADR-0008](0008-lounge-presence.md)의 라운지 목록은 Realtime Presence에 지금 잡혀 있는 회원만 보여준다. 실제로 써 보니 재연결 뒤 track을 다시 안 보내거나(v0.4.1에서 수정), App Nap으로 하트비트가 밀려 연결이 끊기면 회원이 아예 없는 사람처럼 사라졌다. 몇 명뿐인 초대 라운지에선 "누가 있는 곳"이라는 감각이 더 중요하다.

## 고려 요소

- 접속이 흔들려도 회원이 "없는 사람"이 되지 않을 것
- 팝오버는 스크롤 없이 한 화면 (DESIGN.md §4)
- 서버 쓰기는 RPC로만 ([ADR-0003](0003-server-authoritative-rpc.md)), 옛 앱이 깨지지 않을 것

## 고려한 선택지

1. 지금처럼 Presence만
2. **명부(닉네임을 정한 회원) + Presence 상태를 덮어 쓰기**
3. 명부 화면을 따로 (팝오버 안 다른 화면)

## 결정

선택: "2".

- 명부: `players`에서 `named = true`인 회원, 최근에 본 순으로 100명까지. "손님 XXXXXX"는 이름을 정하기 전 계정이라 뺀다
- 마지막으로 본 시각: `players.last_seen_at`. 앱이 켜져 있는 동안 `touch_seen()` RPC를 2분마다 부르고, 서버는 1분 안의 중복을 쓰지 않는다. 옛 앱도 토큰 환전(`token_claims`) 때 트리거로 같이 갱신된다
- 정렬: 보는 중 → 429 VIP → 코딩 중 → 접속 중 → 쉬는 중 → 오프라인(최근에 본 순). 오프라인 칩은 `이름 · 3시간 전`, `dim`
- 헤드라인: 오프라인 회원이 있으면 `라운지 3/12명`(접속 중 / 전체), 없으면 `라운지 3명`
- 명부는 3분마다, 처음 보는 회원이 라운지에 들어오면 바로 다시 읽는다
- 함께: 팝오버를 닫아 둔 앱이 App Nap에 걸리지 않게 `beginActivity(.userInitiatedAllowingIdleSystemSleep)`. 맥 자체의 잠자기는 막지 않는다

### 결과

- 좋은 점: 접속이 끊겨도 회원이 사라지지 않고 "12분 전"으로 남는다
- 좋은 점: 옛 앱 회원도 칩을 받는 동안은 마지막으로 본 시각이 갱신된다
- 나쁜 점: 회원이 수십 명이 되면 두 줄 + `+N명`에 오프라인이 대부분 가려진다. 그때 3을 다시 본다
- 나쁜 점: 마지막으로 본 시각이 모든 회원에게 보인다. 상태 공유 끄기 설정이 생기면 같이 숨긴다
