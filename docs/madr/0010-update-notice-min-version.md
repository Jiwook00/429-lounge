# 업데이트: 자동 설치 대신 앱 안 안내 + 서버 최소 버전

## 배경과 문제

zip 배포([ADR-0007](0007-remote-supabase-zip-distribution.md))엔 업데이트 채널이 없어서 회원이 새 버전을 모른다. 게다가 결과·칩이 서버 RPC에만 있어서([ADR-0003](0003-server-authoritative-rpc.md)) RPC 시그니처를 바꾸는 마이그레이션이 올라가면 옛 앱은 그냥 깨진다.

## 고려 요소

- ad-hoc 서명이라 빌드마다 서명 신원이 바뀐다. 업데이트 서명 검증이 의미가 약하다
- `scripts/install.sh`가 이미 "앱 끄기 → 덮어쓰기 → 다시 켜기"를 한다
- 회원은 Claude Code 사용자: 터미널 한 줄은 괜찮다
- 깨지는 버전은 알림이 아니라 막아야 한다

## 고려한 선택지

1. Sparkle (appcast + EdDSA)
2. 앱이 직접 zip을 받아 교체 (원클릭)
3. **새 버전 안내 + 설치 명령 복사**, 그리고 **서버 최소 버전으로 테이블 막기**

## 결정

선택: "3". 지금 빠진 건 "새 버전이 나온 걸 아는 것"뿐이고, 설치는 이미 스크립트가 한다.

- 최신 버전: `github.com/<repo>/releases/latest`의 302 `Location`에서 태그를 읽는다. API가 아니라서 비인증 한도(시간당 60회)가 없다. 앱을 켤 때와 30분마다
- 최소 버전: 한 줄짜리 `client_policy.min_version`. anon도 읽고 쓰기는 마이그레이션으로만. RPC를 깨는 마이그레이션이면 같은 파일에서 올린다
- 비교는 `LoungeCore`의 `AppVersion` / `AppUpdate.check`. 번들 없는 개발 실행("dev")은 안내하지 않는다
- 화면: 새 버전이 있으면 OPEN 위 버전 라벨이 시안 `vX.Y.Z 나옴`으로 바뀌고, 누르면 게임 타일 자리에 업데이트 카드(설치 명령 · 복사 · 바뀐 점). 최소 버전 미달이면 카드가 닫히지 않고 테이블에서 일으켜 세운다

### 결과

- 좋은 점: 서버·서명 파이프라인 추가 없음. 깨지는 배포를 회원이 에러 대신 안내로 만난다
- 나쁜 점: 회원이 직접 터미널에 붙여 넣어야 한다
- 나쁜 점: 이 기능이 없는 v0.3.0 이하 앱은 최소 버전을 모른다. 그 회원들에겐 한 번은 따로 알려야 한다
- 나쁜 점: 클라이언트에서만 막는다. 옛 앱이 RPC를 직접 부르는 건 막지 않는다 (보안이 아니라 안내 목적)
- 나중에: 필요하면 2(원클릭 교체)를 얹는다. 공개 배포 땐 Developer ID + Sparkle로 새 ADR

## 선택지별 장단점

### Sparkle

- 좋음: 표준, 백그라운드 설치, 릴리스 노트 UI
- 나쁨: appcast 호스팅과 EdDSA 서명 단계. ad-hoc 서명이면 앱 관리 권한 팝업 위험. 초대 단계엔 과함

### 앱이 직접 교체

- 좋음: 버튼 하나, quarantine 문제도 없음 (URLSession으로 받은 파일엔 안 붙는다)
- 나쁨: 교체·재실행 헬퍼를 직접 유지. 안내만으로 부족할 때 해도 늦지 않다
