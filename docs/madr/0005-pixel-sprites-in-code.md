# 도트 스프라이트는 코드 격자로, 폰트는 Galmuri

## 배경과 문제

비주얼 방향은 픽셀 아트로 정했다. 메뉴바 팝오버(폭 340pt)처럼 좁은 창에서도 또렷해야 하고, 디자인 무드는 아직 정해지지 않아 에셋이 자주 바뀔 예정이다.

## 고려 요소

- 레티나에서 도트가 뭉개지지 않을 것
- 무드가 정해지기 전까지 에셋을 빠르게 바꿀 수 있을 것
- 한글이 들어간 도트 폰트

## 고려한 선택지

1. PNG 에셋 + `.interpolation(.none)`
2. 코드 안의 문자 격자(`PixelSprite`)를 `Canvas`에 정수 배율로 그리기
3. 시스템 폰트 + SF Symbols

## 결정

선택: "코드 격자". 스프라이트는 `Sprites.swift`에 문자 배열 + 팔레트로 정의하고, `PixelView`가 칸마다 사각형을 정수 배율로 찍는다. 폰트는 [Galmuri](https://github.com/quiple/galmuri) (SIL OFL 1.1)를 앱에 포함하고 지정 크기(12pt, 10pt)와 그 정수배만 쓴다.

### 결과

- 좋은 점: 보간이 원천적으로 없어서 어떤 배율에서도 또렷함. 팔레트만 바꾸면 변형(예: 황금 칩) 생성
- 좋은 점: 에셋 파이프라인 없이 코드 리뷰로 스프라이트 변경을 볼 수 있음. 스냅샷으로 바로 확인
- 나쁜 점: 큰 스프라이트나 애니메이션 프레임이 많아지면 코드로 관리하기 버거움. 정식 스프라이트 시트가 나오면 PNG 로더를 추가할 수 있음 (그때 새 ADR)
- 나쁜 점: Galmuri 폰트 파일이 약 17MB로 앱 용량이 커짐. 필요하면 서브셋 고려

## 선택지별 장단점

### PNG 에셋

- 좋음: 디자인 도구에서 바로 가져옴. 큰 그림에 유리
- 나쁨: 지금은 그릴 사람도 확정된 무드도 없음. 배율·보간 설정을 매번 신경 써야 함

### 시스템 폰트 + SF Symbols

- 좋음: 가장 쉽고 가벼움
- 나쁨: 도트 감성과 맞지 않음
