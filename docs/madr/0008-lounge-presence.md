# 라운지 접속 정의: "라운지에 있음" + "보는 중" 두 단계

## 배경과 문제

회원들이 같이 있다는 느낌을 주려면 "지금 누가 접속해 있나"를 보여줘야 한다. 그런데 메뉴바 앱은 팝오버를 몇 초 열었다 닫는 게 전부라서, "앱을 열어 보고 있는 사람"만 접속으로 치면 숫자가 거의 항상 0~1이고 라운지가 텅 비어 보인다. 반대로 "앱이 켜져 있으면 접속"만 쓰면 숫자는 넉넉하지만 생동감이 없다.

## 고려 요소

- 라운지가 비어 보이지 않을 것
- "지금 같이 있다"는 순간감
- 개인 정보: 프로젝트, 토큰 양, 대화 내용은 내보내지 않음
- 서버 비용과 운영 부담 없음

## 고려한 선택지

1. 팝오버를 연 사람만 접속
2. 앱이 켜진 사람만 접속
3. 두 단계: 라운지에 있음(앱 켜짐) + 보는 중(팝오버 열림), 여기에 대략적인 Claude 상태

## 결정

선택: "두 단계 + Claude 상태".

- **라운지에 있음**: 앱이 실행되는 동안 Realtime Presence 채널 `lounge`에 상시 접속. 맥이 잠들거나 앱을 끄면 Presence가 알아서 뺀다. 헤드라인 숫자("라운지 12명")는 이 기준
- **보는 중**: 팝오버 창이 실제로 화면에 보이는지(창의 occlusion·key 상태)로 판정. SwiftUI onAppear/onDisappear는 팝오버를 닫아도 안 불릴 때가 있어서 창을 직접 본다. 시안 네온으로 강조
- **위치**: 라운지 / 홀짝 / 슬롯. 게임 타일 인원("TABLE · 2명 앉음", 슬롯 "2명")은 "보는 중 + 그 화면"인 다른 회원 수
- **Claude 상태**: 로컬 로그에서 계산한 대략적인 값만 보낸다. 429 리밋이면 `vip`, 마지막 활동 5분 안이면 `coding`, 30분 넘으면 `resting`, 그 사이는 표시 안 함. 기본으로 켬
- Presence 상태는 바뀔 때만 다시 보낸다(로그 스캔 30초 주기, 팝오버 열고 닫을 때, 화면 이동, 이름 변경)

전광판은 접속과 별개로, 서버가 정산하면서 `lounge_events`에 기록한 특별한 이벤트(잭팟, 큰 승리)만 3분 동안 보여준다. 이벤트는 트리거로 기록해서 클라이언트가 조작할 수 없다.

### 결과

- 좋은 점: 앱만 켜 두면 라운지가 살아 있어 보이고, 팝오버를 연 순간 다른 회원이 보는 중이면 "같이 있다"가 바로 보인다
- 좋은 점: "코딩 중 / 429 VIP / 쉬는 중"은 이 앱만 가진 데이터라 참여감의 핵심이 된다
- 나쁜 점: 상태 공유를 끄는 설정이 아직 없다. 필요해지면 바닥 줄에 토글을 둔다
- 나쁜 점: 같은 계정으로 앱을 두 개 띄우면 Presence 키가 같아 하나로 합쳐진다 (실사용에선 드묾)
- 나쁜 점: Free 플랜 동시 연결 200개 제한. 초대 회원 규모에선 충분

## 선택지별 장단점

### 팝오버를 연 사람만

- 좋음: 정의가 단순하고 정확함
- 나쁨: 대부분의 시간에 0명. 라운지가 늘 비어 보임

### 앱이 켜진 사람만

- 좋음: 숫자가 넉넉함
- 나쁨: 지금 같이 보고 있는지 알 수 없어 순간감이 없음
