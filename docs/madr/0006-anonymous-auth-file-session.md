# 익명 로그인 + 파일 세션 저장

## 배경과 문제

서버가 "누가 베팅했는지"를 알아야 RLS와 칩 지갑이 동작한다. 하지만 라운지에 들어오는 데 별도 가입 절차를 넣고 싶지 않다. 개발 중에는 봇 여러 개가 각자 다른 유저여야 한다.

## 고려 요소

- 설치하고 바로 플레이
- 서버에서 `auth.uid()`로 본인 확인 가능
- ad-hoc 서명 앱에서 키체인 접근 프롬프트가 뜨지 않을 것
- 한 기기에서 여러 유저(봇) 분리

## 고려한 선택지

1. Supabase 익명 로그인 + 기본 키체인 저장
2. Supabase 익명 로그인 + 파일 저장 (프로필별 디렉터리)
3. Sign in with Apple / GitHub OAuth

## 결정

선택: "익명 로그인 + 파일 저장". `supabase.auth.signInAnonymously()`로 기기마다 유저를 만들고, 세션은 `~/Library/Application Support/429Lounge/sessions/<host>-<port>/<profile>/`에 파일로 저장한다. 앱은 `default`, 봇은 `bot-<이름>` 프로필을 쓴다. 저장된 세션의 유저가 사라졌으면(로컬 DB 리셋 등) 자동으로 다시 가입한다.

### 결과

- 좋은 점: 첫 실행에 바로 테이블에 앉음. 봇과 앱이 서로 다른 유저
- 나쁜 점: 기기를 바꾸거나 세션 파일을 지우면 지갑을 잃음
- 나쁜 점: 닉네임이 macOS 사용자 이름이라 회원끼리 겹치거나 알아보기 어려울 수 있음 (닉네임 설정 UI 필요)
- 나쁜 점: 세션 토큰이 파일로 남음 (`completeFileProtection` 적용). 칩 외에 지킬 자산이 없어서 허용
- 나중에: 익명 유저를 OAuth 계정에 연결(link)해서 기기 간 지갑 유지 가능. 그때 새 ADR

## 선택지별 장단점

### 키체인 저장

- 좋음: 기본값, 더 안전함
- 나쁨: ad-hoc 서명 앱은 빌드마다 서명이 바뀌어 접근 프롬프트가 뜰 수 있음. 봇 분리도 번거로움

### OAuth

- 좋음: 기기 간 지갑 유지, 회원 식별이 쉬움
- 나쁨: 프로토타입엔 진입 장벽. 리디렉션 URL 설정 등 부가 작업
