# Codex CLI 로그도 읽고, 황금 칩은 도구마다 준다

## 배경과 문제

Codex CLI 사용자도 라운지에 들어올 수 있게 Codex 세션 로그(`~/.codex/sessions/**/*.jsonl`)를 읽기로 했다. 두 도구를 함께 쓰는 회원의 토큰과 429를 어떻게 셀지 정해야 했다. 특히 황금 칩은 "코딩을 못 하는 그 시간"에 주는 보너스인데, Claude만 막히면 Codex로는 계속 코딩할 수 있다.

## 고려 요소

- 서버 함수(`claim_tokens`, `claim_golden`)는 고치지 않을 것
- 토큰 칩의 원칙("많이 쓰는 사람이 더 받는다", ADR-0004)과 맞을 것
- 소규모 라운지라 악용 방지보다 단순함

## 고려한 선택지

1. 하나만 걸려도 지급: 도구마다, 리밋마다 황금 칩
2. 둘 다 막혔을 때만 지급
3. 도구마다 지급하되 VIP HOUR는 전부 막혔을 때만

## 결정

선택: "하나만 걸려도 지급". 이유: 토큰 칩과 같은 방식이라 일관되고 판정 로직이 늘지 않는다. 두 도구를 쓰는 회원이 황금 칩을 더 받는 건 요금제 차이를 인정하는 것과 같은 결과라 받아들인다.

### 결과

- 토큰: 클라이언트가 Claude + Codex의 fresh를 합쳐 `claim_tokens`에 한 번 보낸다. 따로 보내면 서버가 차액만 줘서 큰 쪽만 받게 된다
- 429: 걸려 있는 리밋마다 `claim_golden`을 부른다. Codex는 창 길이로 `five_hour`/`seven_day`에 맞춘다
- Codex는 같은 리밋의 `resets_at`이 초 단위로 흔들려서, 클라이언트에서 종류가 같고 10분 안이면 처음 기록으로 고정한다 (서버는 `resets_at`으로 중복 지급을 막기 때문)
- 나쁜 점: Codex 429 판정(창 `used_percent` ≥ 100 또는 `rate_limit_reached_type`)은 실제로 걸린 로그로 아직 확인하지 못했다

## 선택지별 장단점

### 둘 다 막혔을 때만 지급

- 좋음: 황금 칩 콘셉트에 가장 충실하다
- 나쁨: 어떤 도구를 쓰는지 알아야 판정할 수 있다. 한 도구만 쓰는 회원을 따로 처리해야 한다

### VIP HOUR만 전부 막혔을 때

- 좋음: 칩은 공평하게 주면서 VIP 연출은 아낀다
- 나쁨: 황금 칩은 있는데 VIP가 아닌 상태가 생겨서 설명하기 어렵다
