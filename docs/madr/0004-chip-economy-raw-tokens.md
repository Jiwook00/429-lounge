# 칩은 토큰 사용량 그대로 (요금제 보정 없음)

## 배경과 문제

Claude Code 토큰 사용량을 칩으로 바꾼다. 요금제(Pro, Max 등)마다 쓸 수 있는 양이 달라서, 그대로 바꾸면 비싼 요금제 사용자가 칩을 훨씬 많이 받는다. 이걸 보정할지 정해야 했다.

## 고려 요소

- 공정함 vs 단순함
- 로컬 로그만으로 계산 가능할 것 (로그에는 내 한도가 429에 걸렸을 때만 기록된다)
- 토큰을 일부러 낭비하게 만드는 동기는 약할 것

## 고려한 선택지

1. 토큰 절대량 그대로 (보정 없음)
2. 한도 대비 사용률(%)로 보정
3. 로그 스케일 등 많이 쓸수록 덜 주는 체감 공식

## 결정

선택: "토큰 절대량 그대로". **요금제 차이는 인정하고, 칩은 게임 실력과 운으로 따면 된다**는 방향(사용자 결정).

- 기준은 **fresh 토큰**(입력 + 출력 + 캐시 쓰기). 캐시 읽기는 fresh의 10배 안팎이고 작업량과 비례하지 않아서 제외
- 1,000 fresh 토큰 = 1칩, 상한 없음 (서버는 하루 5천만 이상만 거절)
- 격차를 줄이는 장치는 따로 둔다: 출근 도장(+100), 파산 구제(+300), 리밋에 걸리면 황금 칩

상세 규칙은 [docs/chip-economy.md](../chip-economy.md).

### 결과

- 좋은 점: 계산이 단순하고 로그만으로 정확함. 메뉴바 숫자가 코딩하는 만큼 오르는 직관적인 피드백
- 나쁜 점: 헤비 유저와 라이트 유저의 칩 격차가 큼. 실제로 돌려보고 베팅 단위나 보너스를 조정해야 할 수 있음
- 나쁜 점: 토큰을 더 쓰면 칩을 더 받는 구조라 낭비 동기가 약간 있음. 1,000:1 환율이라 영향은 작다고 판단

## 선택지별 장단점

### 사용률(%) 보정

- 좋음: 요금제와 무관하게 공정
- 나쁨: 로그에는 한도가 429에 걸렸을 때만 남아서 평소 사용률을 알 수 없음

### 체감 공식

- 좋음: 격차 완화, 낭비 동기 감소
- 나쁨: 숫자가 직관적이지 않음. "많이 쓴 사람이 많이 받는다"는 결정과 어긋남
