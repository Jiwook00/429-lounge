# 429 드롭: 격자 플링코 + 파친코 포켓, 서버가 경로를 정하고 환수율은 DP로

> 칸 배수, 포켓 확률, FEVER 수치는 [ADR-0019](0019-429-drop-letters-vip-fever.md)에서 바꿨다. 구조(격자, 레인, 특수 핀, DP)는 그대로다.

## 배경과 문제

슬롯처럼 연타하는 숏폼 게임을 하나 더 원했다. 플링코(공이 핀에 튕겨 배수 칸에 들어감)에 파친코의 발사 손맛, 스타트 포켓, FEVER를 합친다. 조작(레인, 파워 타이밍)이 있지만 결과와 칩은 서버가 정해야 하고(ADR-0003), 조작이 환수율을 크게 흔들면 안 된다.

## 고려 요소

- 결과는 서버, 클라이언트는 재생만 (ADR-0003)
- Postgres 함수로 짤 수 있을 만큼 단순할 것
- 환수율을 손계산이나 시뮬레이션 감이 아니라 정확히 맞출 수 있을 것
- 조작은 손맛과 리스크 모양만, 기대값은 거의 같게
- 340pt 팝오버, 정수 배율 픽셀

## 고려한 선택지

1. 서버에서 물리 시뮬레이션 후 충돌 시퀀스 전송
2. 격자 모델: 줄마다 왼쪽·오른쪽 한 비트
3. 결과(칸)만 정하고 경로는 클라이언트가 그럴듯하게 생성

## 결정

선택: "격자 모델". 이유: 경로가 비트열이라 서버 함수가 짧고, 클라이언트는 핀 사이를 이어 그리기만 하면 된다. 공끼리 영향이 없어서 (줄, 칸, 분열 여부) 위의 DP로 기대값을 정확히 계산할 수 있다. 3번은 특수 핀(골드·분열·포켓)이 경로에 달려 있어 맞지 않는다.

- 보드: 12줄, 줄 r에 핀 r+3개, 칸 13개. 배수 `16 4 1.8 1.3 1.0 0.6 0.4 0.6 1.0 1.3 1.8 4 16`
- 레인 3개. 옆 레인 입구 핀은 공을 안쪽으로 미는 가이드 핀이라, 옆 레인 공은 가운데 공이 그쪽으로 튄 것과 같다. 보드가 좌우 대칭이면 세 레인의 기대값이 정확히 같고 다른 건 첫 방향뿐이다
- 특수 핀: 골드(최종 배수 +0.3), 분열(공 하나당 한 번), 스타트 포켓(미니 3릴, 1/8로 FEVER, 아니면 20% 환급). 폭발 핀은 공끼리 상태를 공유해 DP를 깨므로 보류
- FEVER: 같은 응답에 공 15개, 배수 ×2, 분열 없음. 기준 금액은 포켓에 들어간 공의 건 칩
- 파워는 경로에 영향이 없다. 게이지 24칸에서 뗀 칸으로 등급만 정한다: 가운데 1칸 PERFECT, 양옆 2칸씩 GOOD. 등급은 포켓이 공을 잡을 확률을 올린다(전동 튤립). 서버가 파워 값(0~1000)으로 직접 판정한다
- 환수율: 기본 98%, GOOD 98.5%, PERFECT 99%. 모든 레인에서 같다. AUTO는 파워를 매번 랜덤으로 쏴서 약 98.13%
- 계산기: `scripts/drop_ev.py` (DP + 무작위 검증). 수치는 이 파일과 서버 함수, `docs/chip-economy.md`를 같이 고친다
- 이름은 429 드롭, 코드·DB 식별자는 `plinko` (SQL 키워드 `drop`과 헷갈리지 않게)

### 결과

- 좋은 점: 서버 함수가 짧고 환수율이 정확하다. 레인 균형을 숫자 조정 없이 구조로 맞췄다. 결과가 응답에 다 있어서 재연결·Realtime이 필요 없다
- 나쁜 점: 결과가 공보다 먼저 도착하므로 클라이언트가 지갑·전광판 반영을 착지까지 미뤄야 한다. 등급 판정은 서버가 하지만 파워 값은 클라이언트가 만들어서, 스크립트로 항상 PERFECT를 보낼 수 있다(상한 99%라 칩이 늘지는 않는다). FEVER가 환수율의 약 8%p를 차지해서 단기 결과의 분산이 크다
